# 汉字定位库：第一期开发计划

2026-10-24

依据 [调研报告](调研报告.md)。本计划只覆盖第一期：一般图书、古籍刻印本、古籍手写本。第二期碑帖不实施，只要求结果格式以后还能装下它。

## 1. 完成时库能做什么

对一张页面图，按所选版式给出：

- 每个字的四点框、朝向、识别出的字和字级置信度。识别结果一律记录，错字不影响通过
- 每一行或每一列的四点框、行文本和行置信度
- 若干条语流：正文、夹注、标题、眉批或旁批、版心。每条语流的文本由其中的字按顺序拼成
- 按框拉正后的字图

调用方式保持薄：

```python
from hanloc import locate, crop_glyph

page = locate(image, profile="book")       # 或 "woodblock" / "manuscript"
patch = crop_glyph(image, page.glyphs[0], margin=0.15)
```

命令行把同一结果写成 JSON、叠加图和字图目录，供存档：

```text
python -m hanloc locate page.jpg --profile book --out out/
```

另有一个只监听本机的调试页，用来眼看框、顺序、识别文字和裁图。见第 4 节。

包名 `hanloc` 先用这个，以后改名只动打包配置。

## 2. 技术选择

Python 3.11 或 3.12，项目根目录使用 `.venv`。依赖分成三层：

| 层 | 依赖 | 原因 |
| --- | --- | --- |
| 核心 | `numpy`、`opencv-python-headless` | 几何、透视裁切、把叠加图写成 PNG。无窗口，避免和带 GUI 的 OpenCV 冲突 |
| 检测 `ocr` | `rapidocr`、`onnxruntime` | 行/列检测、识别，以及印刷体单字回推。模型随 wheel 自带，默认 ONNX、CPU |
| 调试页 `view` | `fastapi`、`uvicorn` | 本机视觉调试。不装进核心包 |

`rapidocr` 是正在维护的包；旧的 `rapidocr_onnxruntime` 不再使用。接入时锁定当时的 3.x 小版本。检测参数走它的 `params` 字典，第一期要用到的是：

| 版式 | 参数 |
| --- | --- |
| `book` | `Global.use_cls=true`，`Global.max_side_len=2000`，`Det.unclip_ratio` 用默认 1.6 |
| `woodblock`、`manuscript` | `Global.use_cls=false`，`Global.max_side_len=4000`。`Det.unclip_ratio` 先用 1.3，样张上若邻列粘连再降、若框裁掉笔画再升 |

三个版式都设 `Global.use_rec=true` 和 `Global.return_word_box=true`。RapidOCR 返回的行框、行文本 `txts`、行置信度 `scores`，以及 `word_results` 里每个字的文本、置信度和框，都写入页面结果。不保存模型耗时。

- `book` 与 `woodblock`：单字框来自回推。每个 `Glyph` 带上对应的字和字级置信度，`Line.text` 用该行的 `txts`。
- `manuscript`：单字框仍由列内墨迹切分。列的 `Line.text` 和 `Line.score` 照实保存。只有墨迹框数量与 `word_results` 字数一致时，才把字和字级置信度抄到对应 `Glyph`；数量不一致时字框的 `char` 留空，整列文本仍在 `Line.text`。

`Flow.text` 由该条语流里的字按顺序拼成，不单独再识别一次。几何、裁切、语流不导入 RapidOCR。未安装 OCR 依赖时，手工框仍可构成 `Line` 和 `Glyph`，识别字段为空，核心测试仍然能跑。

## 3. 仓库

```text
src/hanloc/
  types.py          # Line、Glyph、Flow、Page、Profile
  geometry.py       # 四点框、朝向、旋转映回、相对间距
  crop.py
  flow.py           # 只吃框
  split.py          # 回推、字格、墨迹切分
  detect.py         # RapidOCR 适配器
  profiles.py       # book / woodblock / manuscript
  pipeline.py       # locate
  cli.py
  view.py           # 本机调试页
  static/index.html
tests/
samples/            # 本地样张，不提交
pyproject.toml
```

`src` 布局，避免在仓库根目录直接跑到未安装的源码。类型用 `dataclass`。公开对象在写成 JSON 时字段稳定：`quad` 为四个 `[x, y]`，顺序左上、右上、右下、左下；坐标是原图像素，y 向下。

`Line` 有四点框、朝向、`text`、`score`。`Glyph` 有所属 `line_id`；字框来自 `word_results` 时 `char` 与 `score` 必填。`Flow` 有有序的字形编号和拼出来的 `text`。

## 4. 本机视觉调试页

命令行结果供存档。调试页只监听 `127.0.0.1`，用来眼看框和顺序。不引入 React 或 Vue，也不单独做前端工程。

- 启动：`python -m hanloc.view`，浏览器打开本地页面。
- 页面是一张静态 HTML，用 canvas 把框画在图上。`POST /api/locate` 接收图片和版式名，返回与 `page.json` 相同的结构。`GET /api/crop` 按字形编号返回拉正后的字图。
- 可切换版式 `book`、`woodblock`、`manuscript`。图层可分别开关：行/列框、单字框、语流序号、识别出的字。点击一个字，侧栏显示它的字、字级置信度、所属行文本、角色，以及裁图。不确定的框用另一种描边。
- 也可打开已有的 `page.json` 只查看，不重新识别。M1 用手工框试画布，M2 再接上 `locate`。

## 5. 里程碑

一步做完、用它的完成标准看过，再做下一步。

### M0　骨架

建立 `.venv`、`pyproject.toml`、包目录和 `python -m hanloc --help`。核心依赖可装。OCR 与调试页写成 extra：`pip install -e ".[ocr]"`、`pip install -e ".[view]"`。

完成标准：空环境下 `pip install -e .` 后能导入 `hanloc`，且不下载模型。

### M1　几何、裁切、语流

不接检测器。用手工框驱动。

`geometry` 提供：由第一条边计算朝向；两点框是否因相对字号而分开；整页顺时针转 90° 后，把检测点映回原图。映回公式用原图高度 `H`：`x = y_rot`，`y = H - 1 - x_rot`。用若干已知点做单元测试，包括转回去后与原点一致。

`crop_glyph` 用四点做透视变换，四周按框尺寸的比例留白。测试一张画了倾斜矩形的合成图，裁完后矩形边与图像边平行。

`flow` 实现两种约定：

- `horizontal_ltr`：左右几乎不重叠的框先分成栏，栏从左到右；栏内按上边从上到下；一行内的字按左边从左到右。
- `vertical_rtl`：按中心的 x 分列，间隙用列宽的比例而不是固定像素；列从右到左；列内从上到下。

角色在这一阶段只占字段。版心和夹注的规则放到 M3，避免 M1 同时处理版式特例。

同时做出调试页的查看能力：打开一张图和一份手工写成的 `page.json`，在画布上画出框。此阶段不调用 `locate`。

完成标准：合成框的顺序与手写期望一致；裁图测试通过；调试页能按 `page.json` 画出框。此阶段测试不读取 `samples/`。

### M2　图书页面

适配 RapidOCR。`locate(..., profile="book")` 的顺序是：检测行框 → 用 `word_results` 生成单字框 → `horizontal_ltr` 收成语流。页眉、页码若自成一行，先仍算正文；分栏必须分开。

命令行写出：

- `page.json`：行、字形、语流、所用版式名。每行有文本和置信度，每个单字框有字和字级置信度
- `overlay.png`：框和语流序号
- `crops/`：拉正的字图

调试页从这一步起可以提交图片并选择版式，结果与 `page.json` 相同。M2、M3、M4 的目视验收在这个页面上做。

完成标准：两张横排书页（一张单栏、一张双栏）上，行框沿文字行走，单字框盖住字身，双栏没有串栏，裁图不含邻字。`page.json` 中每行有文本和置信度，每个单字框有字和字级置信度。个别错字忽略。

### M3　刻印本

`woodblock` 在送入检测前把页面顺时针转 90°，检测后映回。关闭方向分类，放宽 `max_side_len`，减小 `unclip_ratio`。语流用 `vertical_rtl`。

夹注：一列里高度低于该列字高中位数一定比例的字，收成双行小字。比例先定为 0.7，写在版式配置里。小字再按 x 分成左右两行，先右后左，嵌回它们在正文中的纵向位置，角色为 `commentary`。

版心：配置项 `centerfold`，取值 `none`、`gutter`、`left`、`right`，默认 `none`。半页的版心在左缘或右缘，筒子页在中缝，不能写死成「页面中心」。命中的窄列角色为 `centerfold`，不进入正文语流。

完成标准：一张普通竖排刻本书影上，列从右到左可顺读，邻列不粘连。若样张含双行夹注，夹注单独成角色且先右后左。版心只在样张确实有、并且 `centerfold` 设对时验收。`page.json` 中每列有文本和置信度，每个单字框有字和字级置信度。

### M4　手写本

检测与列序沿用 `woodblock`。单字不再回推：把列框拉直后做水平投影（列在阅读方向上已变成横条），按墨迹间隙切开，间隙阈值相对字高。左右结构被拆开、或两字粘连时，该框标 `uncertain=true`，仍给出一个框。

完成标准：一张列大致可辨的楷书或行书抄本上，列序可顺读；多数字各有一框。允许少量粘连和拆散，这些框带不确定标记。不要求处理涂改文字的语义，涂改块保持不确定即可。每列有文本和置信度。墨迹框数量与识别字数不一致的列，字框不填字，整列文本留在 `Line.text`。

## 6. 样张

样张放在 `samples/`，加入 `.gitignore`。每张配一个纯文本说明：版式、是否双栏、是否有夹注、版心在哪。第一期一共六张就够：

| 里程碑 | 样张 |
| --- | --- |
| M2 | 横排单栏一页，横排双栏一页 |
| M3 | 竖排刻本一页；有双行夹注的一页（可与前一张是同一张） |
| M4 | 楷书或行书抄本一页，列大体分开 |

M0、M1 不需要样张。检测器在样张上的测试标成手动：不进默认的 `pytest`，避免每次测试都加载模型。需要时单独跑 `pytest -m sample`。

## 7. 测试与日常检查

- 单元测试覆盖映回、分栏、分列、夹注分组、裁切。输入用合成坐标和合成图。
- `ruff` 检查未使用导入和基本风格。类型标注写在公开函数上，第一期不引入单独的类型检查器。
- 目视验收在调试页上只看三件事：框是否沿字列、序号是否能顺读、裁图是否带上邻字。识别对错不作为通过条件。

## 8. 第一期不做

不自建识别器，不以识别对错验收。RapidOCR 的行级和字级结果完整保存。不训练模型，不接 PaddleOCR 第二套后处理，不做通用产品界面。本机调试页保留。不做印章、狂草、甲骨、视频和切块检测。切块检测只在 `pipeline` 的注释里标为第二期入口。不确定标记和「一页多条语流」在 M1 的数据结构里就留好，M4 开始真正写入。

## 9. 建议的动手顺序

1. M0、M1 可以马上做，不依赖样张。
2. M2 开始前放入两张图书页。
3. M2 通过后做 M3；夹注比例和 `unclip_ratio` 只按样张调，不预先多做开关。
4. M4 最后做。墨迹切分只对已经分对的列负责。

M2 若在单栏书页上就框不对，先查 `max_side_len` 和框膨胀，不提前进入刻本特例。
