# 汉字定位库：调研与分期设计

2026-10-24

库的任务是：在一张图上找出汉字的外框，排成可供重建语流的顺序，并按外框裁出字图。认字可以后接，前两期都不以识别为目标。

## 1. 设想与范围

最初的材料设想很宽：一般图书、书法与碑帖、刻石与甲骨、视频或照片上零散的字。字号、位置和朝向都可以差得很大。库只提供基础能力，供下游重建语流和裁字。

分期收窄如下。

| 阶段 | 场景 | 本阶段要稳住的版式 |
| --- | --- | --- |
| 第一期 | 一般图书页面；古籍刻印本；古籍手写本 | 横排书页；竖排、有栏或大致成列的书页 |
| 第二期 | 碑帖 | 字号悬殊、列不齐、破损和印章 |
| 以后 | 刻石照片、甲骨、视频中的零散文字 | 透视、裂纹、任意朝向、跨帧 |

第一期的手写本指楷书、行书抄本和稿本，字大体还能分开。连笔狂草放到第二期，与碑帖一起处理。

## 2. 调研结论

### 2.1 外框与方向

中文检测的事实标准是**四点框**（左上、右上、右下、左下）。水平矩形只适合基本摆正的书页；字或列一斜，裁图就会带上邻字。弯曲文字用的多边形，前两期用不到。

方向是两件事，都记在框上，不记在整页上：

- **字的朝向**：第一条边相对图像横轴的角度。裁切时用它把字拉正。
- **阅读走向**：字与字沿哪条轴排列。横排沿水平往下分行，竖排沿竖直分列。一页可以有多套走向，例如横额加竖列。

另有一种 0°/180° 分类，只用于识别前把裁下来的行图转正。它不改变四个角，也不代替阅读走向。PaddleOCR 的文本行方向分类器是按现代横排训练的，古典竖列上会判错，古籍流水线里应关闭。

单字位置有两条来源：

- **行框回推**：先框住一行或一列，再按识别模型的列位置把框切开。PaddleOCR 的 `return_word_box`、RapidOCR 的 `return_word_box` 都是如此。切出来的接近排版上的字身格。汉字等宽时可用；标点和手写变宽时会偏。RapidOCR 作者也写过，这种切法泛化有限。
- **直接检测单字**：CRAFT 先找字符区域再连成行；书法系统 CalliReader 用 YOLO 只检测「这里有一个字」。字号差得大、列又不齐时，这条路更合适，但没有能同时覆盖图书、刻本和手写本的现成权重。

间距判断用相对字号，不用绝对像素。两个框的中心距若明显大于二者高度的均值，就不算同一个字列。这样大字标题和小字注文可以在同一页上。

整页高清图先缩得很小再检测，小字会消失。碑帖和大开本需要重叠切块、分块检测、再映回全图。第一期的普通书页可以先不做切块，接口上留出这一步。

### 2.2 可以直接用的工具

| 材料 | 能用的部分 | 许可与限制 |
| --- | --- | --- |
| [RapidOCR](https://github.com/RapidAI/RapidOCR) | 现代横排和场景文字的行级四点框；汉字单字框由行框回推。ONNX，Windows 上好装 | 代码与所带 Paddle 模型均为 Apache-2.0 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | 同上，且是 RapidOCR 的上游。竖排检测本身可用 | Apache-2.0。默认流水线容易把结果按横排阅读顺序交出去 |
| [paddleocr-htr-ancient-chinese](https://github.com/Ifena-Xia/paddleocr-htr-ancient-chinese) | 宾夕法尼亚大学图书馆在古籍竖排上的实践：原分辨率检测、整页旋转 90° 再检测、坐标映回、按列从右到左排序、减小框膨胀、可关方向分类 | 脚本，宜吸收做法，不宜整库依赖 |
| [open-guji-cv](https://github.com/open-guji/open-guji-cv) | 刻本流程可参考：版式判断、去书脊与边框、校正、分列、再逐列定字格 | Apache-2.0。项目新、体量小 |
| [MTHv2](https://github.com/HCIILAB/MTHv2_Datasets_Release)（含 TKH、MTH） | 约 3200 张汉文大藏经图像，有字框、按阅读顺序排列的行、以及栏线。密集汉字检测的公开基准 | 仅供学术研究 |
| [SCUT-CAB](https://github.com/HCIILAB/SCUT-CAB_Dataset_Release) | 4000 张古籍的版面标注和阅读顺序，含版心、眉批等，没有单字框 | 仅供学术研究 |

CalliReader（ICCV 2025）证明整页书法可以「单类字检测 + 单独排序」，留到第二期再看权重能否借用。OBIMD、HUST-OBC 属于甲骨，不进入前两期。SongPanda 等模型解决的是刻本识别和双行夹注的文本标记，不是定位。

### 2.3 古籍上已经明确的失败方式

竖排刻印本和抄本上，通用 OCR 常出现同一类错误：字认得出，列切错了。小字页和双行夹注上，检测框会横跨好几列。原因包括检测前把长边缩到一千多像素、框膨胀系数过大、以及方向分类器按横排理解竖列。

已经验证有效的处理是：

1. 在原分辨率上检测（超长边再设上限，避免小字被缩没）。
2. 竖排页先顺时针转 90°，让列变成横行，检测后再把四点映回原图。
3. 框膨胀小于现代文档的默认值，避免邻列粘连。
4. 关闭文本行 0°/180° 分类。
5. 按框中心的横向位置分列，列从右到左，列内从上到下。

双行夹注要在列内再看字号：明显小于该列正文字号的，收成夹注，先右行后左行，再回到正文。版心（鱼尾、卷次、页码）单独成条，不写入正文语流。

## 3. 第一期设计

三种页面共用一套结果，差别放在版式参数里。

### 3.1 结果

一张页输出两类对象。识别文字和置信度随框保存，对错不作为前两期验收。调试时用本机网页查看外框、语流顺序、识别文字和裁图。

**字形** `Glyph`：编号、四点框、朝向角度、置信度。框的含义默认是字身格；若以后收紧到墨迹，另存字面框，不覆盖字身格。

**语流** `Flow`：编号、版式约定、有序的字形编号、角色。角色至少有正文、夹注、标题、眉批或旁批、版心。一页多条语流。顺序是几何草案，允许改序；裁切不依赖顺序。

版式约定第一期只做两种：`horizontal_ltr`（行从上到下，行内从左到右）、`vertical_rtl`（列从右到左，列内从上到下）。

裁切输入是原图和一个四点框，输出是拉正后的字图，四周空白可调。

### 3.2 三种场景

| | 一般图书 | 古籍刻印本 | 古籍手写本 |
| --- | --- | --- | --- |
| 版式 | 横排为主，偶有分栏 | 竖排从右到左；有边栏、界栏、版心 | 竖排为主，列线弱或没有 |
| 字号 | 一行内接近 | 正文稳定；标题、夹注、眉批另一级 | 列内就会变 |
| 检测 | RapidOCR 行框，直接使用 | 同一检测器，走竖排参数；有栏线时可先分列 | 同一检测器，走竖排参数；列框只作为搜索范围 |
| 单字框 | 行框回推。等宽印刷体足够 | 列被正确切开后，用回推或按列高估算的字格 | 列内按墨迹投影或连通域切，宽度随字变化。回推只作对照 |
| 语流 | 先分栏，再自上而下、行内从左到右。页眉页码单独成条 | 列从右到左。双行小字为夹注。版心不进正文 | 与刻印本相同的列序。补字、删改标成不确定，不硬插入正文 |
| 第一期难点 | 分栏、图注、脚注 | 双行夹注、小字、版心 | 字距不匀、列不直、涂改 |

手写本仍先找列，再在列内切字。直接在整页上找单字，容易把污迹和栏线算进去；这一步留给字号和方向都更乱的碑帖。

### 3.3 流水线

```
图像
  → 按版式做轻度预处理（竖排可选旋转 90°；刻本可选校正）
  → 文本检测，得到行或列的四点框
  → 映回原图坐标
  → 过滤版心等非正文区域（刻本）
  → 在每个行/列框内切出单字框
  → 按版式约定收成语流
  → 按需裁字
```

版式参数合成三个配置，而不是三套程序：

- `book`：不旋转；开启一般的行方向分类；使用默认框膨胀；阅读顺序 `horizontal_ltr`；单字用回推。
- `woodblock`：原分辨率；旋转 90° 检测；关闭行方向分类；较小框膨胀；阅读顺序 `vertical_rtl`；分出夹注和版心；单字用回推或字格。
- `manuscript`：与 `woodblock` 相同的检测和列序；单字改为列内变宽切分；补字和涂改标不确定。

检测器包在适配器后面。第一期适配 RapidOCR。PaddleOCR 只作为同一接口的替换，不并列维护两套后处理。

### 3.4 模块

1. `geometry`：四点框、朝向、相对间距、坐标映回。
2. `crop`：按框拉正裁字。
3. `flow`：分列或分行、排序、角色。只吃框，不吃像素。
4. `detect`：RapidOCR 适配器，加上三个版式配置。
5. `split`：行框回推；列内字格；列内变宽切分。

`geometry`、`crop`、`flow` 不引用 OCR 库，便于以后换检测器。

### 3.5 第一期不做

不认字，不处理印章，不做狂草，不做甲骨和视频，不做整页语义（哪一句是注、哪一句是疏的内容判断）。夹注只按字号和位置从正文中分出来。不训练新模型；若三种样张上现成检测器明显失败，再考虑用 MTHv2 一类数据微调，那已是第一期之后的决定。

## 4. 第二期：碑帖

碑帖仍输出同一套字形和语流。要新增的是单字级检测，因为列常常不齐，字号可以从题额差到落款，回推没有一条可靠的列中心线。

可借鉴的结构是 CalliReader：一个只分「是字 / 不是字」的检测器，加上独立的排序。框需要能旋转；第一期的四点框已经满足。破损、印章和极大图幅用切块检测和「不确定块」：一块墨迹对应几个字说不清时，保持整块，不强行切开。

第一期只要把朝向放在单个框上、一页允许多条语流、并允许不确定块，第二期就不必改结果格式。

## 5. 实施顺序

1. 实现四点框、裁切和两种阅读顺序，用手工框验证。
2. 接入 RapidOCR，先跑通 `book`：横排书页的行框、回推单字、语流和裁图。
3. 加上 `woodblock`：旋转检测、映回、从右到左分列，用一种带双行夹注的刻本验收。
4. 加上 `manuscript`：列内变宽切分，用一种列大致可辨的抄本验收。

每一步用固定的几张样张看框是否贴住字列、顺序是否可顺读、裁图是否含邻字。识别对错不作为验收项。

## 6. 风险

- 现成检测器在双行小字和淡墨抄本上仍可能并列或漏列。旋转和原分辨率是第一道办法，不是保证。
- 回推单字框在刻印本上依赖「一列已被切对」。列错了，字格会整列错。
- 手写变宽切分会把左右结构的字拆开，或把相邻两字并住。第一期接受人工改框。
- MTHv2、SCUT-CAB 不能直接拿来再分发。微调若发生，训练数据的许可单独处理。
